# 개발 일지

AI가 만든 코드를 그대로 쓰지 않고, 기능마다 아래 순서로 확인한 뒤 커밋한다.

1. **명세:** 이번 단계에서 무엇이 되어야 하는지 정한다.
2. **검토:** 작성한 코드를 읽고 명세와 수업 구조에 맞는지 확인한다.
3. **실행:** 실제 창으로 띄워 스크린샷(`tools/shot.py`)을 남긴다.
4. **테스트:** 명세를 자동 점검(`tools/check.py`)으로 옮겨 고정 프레임(1/60초)으로 돌린다.
5. **설명:** 어떻게 동작하는지, 왜 그렇게 만들었는지 적는다.

```
C:\Python313\python.exe tools\check.py      # 자동 점검 (창 없이)
C:\Python313\python.exe tools\shot.py       # 스크린샷 (docs/shots/)
C:\Python313\python.exe main.py             # 게임 실행
```

## 1주차: 뼈대와 공유 총알

### 1. 프로젝트 뼈대

**명세**
- `main.py`를 실행하면 1280×720 창에 벽과 나무 바닥이 있는 빈 구역이 뜬다.
- ESC 또는 창 닫기로 종료한다.
- 수업 LEC15의 `game_framework`(모드 스택), `game_world`(레이어) 구조를 그대로 쓴다.

**검토**
- `game_framework.py`: LEC15 코드에 `frame_time`(직전 프레임 시간)만 추가했다. 이동을 프레임 수가 아니라 시간에 비례시키기 위해서다. 창을 끌다 멈춘 경우 한 번에 크게 움직이지 않도록 최대 0.05초로 자른다.
- `game_world.py`: LEC15의 레이어 관리에 충돌 쌍(`add_collision_pair`, `handle_collisions`)을 더했다. 충돌 판정은 `get_bb()` 사각형끼리 겹치는지로 본다. LEC15의 `add_oject` 오타는 `add_object`로 바로잡았다.
- `play_mode.py`: 이벤트 처리를 `dispatch(event)`로 분리했다. 자동 점검이 실제 게임과 같은 경로로 입력을 넣기 위해서다.
- pico2d 1.5.1의 `draw_rectangle(..., filled=True)`로 색을 채운 도형을 그릴 수 있어서, 1~3주차는 이미지 파일 없이 도형으로 개발한다.

**실행**
- `main.py`를 3초 동안 실행해 실시간 루프가 오류 없이 도는 것을 확인했다.
- 스크린샷: `docs/shots/w1_1_skeleton.png`

**테스트** (`tools/check.py`)
- `skeleton_runs_and_esc_quits`: 120프레임 동안 오류 없이 돌고, ESC 입력 시 `game_framework.running`이 꺼진다.

**설명**
- 자동 점검은 SDL 더미 화면으로 창 없이 돈다. 더미 화면에서는 픽셀을 읽을 수 없어서 스크린샷만 실제 창으로 찍는다.
- 상태 머신은 수업(LEC12~15)처럼 `transitions` 라이브러리의 `Machine`을 쓴다. PRD 15-2의 `state_machine.py`는 따로 만들지 않는다.

### 2. 플레이어 이동과 조준

**명세**
- 구역 가운데에서 시작해 WASD로 8방향 이동한다. 속도는 초당 200px이고 대각선도 같은 속도다.
- 반대 방향 키를 함께 누르면 멈춘다.
- 벽 밖으로 나갈 수 없다.
- 항상 마우스 쪽을 바라본다. 마우스를 그대로 두고 움직여도 계속 마우스를 향한다.
- 상태는 IDLE, RUN 두 가지다.

**검토**
- `player.py`: 눌린 키를 집합으로 모아 방향 벡터를 더하고 길이를 1로 맞춘다. 그래서 대각선이 √2배 빨라지지 않고, 반대 키는 서로 지워진다.
- 조준 각도는 마우스 이벤트가 올 때가 아니라 매 프레임 `atan2`로 다시 계산한다. 마우스를 멈춘 채 이동해도 조준이 따라간다.
- SDL 마우스 좌표는 좌상단 원점이라 `HEIGHT - 1 - y`로 뒤집는다.
- `zone.push_out()`: 원의 중심을 벽 안쪽에서 반지름만큼 떨어진 범위로 자른다.
- 다른 모드가 위에 올라오면 키업을 놓치므로 `release_all_keys()`로 모든 키를 뗀 것으로 처리한다 (LEC15 방식).

**실행**
- 스크린샷: `docs/shots/w1_2_move_and_aim.png`. 가운데에서 왼쪽 위로 약 133px(0.67초) 이동한 상태로, 총이 오른쪽 위 마우스를 향한다.

**테스트**
- `move_right_for_one_second`: D를 1초 누르면 x가 200px(±1) 늘고, 떼면 IDLE이 되어 멈춘다.
- `diagonal_has_same_speed`: W+D를 1초 누르면 이동 거리가 200px(±1)이다.
- `opposite_keys_cancel`: A+D를 함께 누르면 IDLE이고 움직이지 않는다.
- `cannot_leave_the_floor`: 왼쪽 아래로 10초 이동해도 벽 안쪽 모서리에서 반지름만큼 떨어진 곳에 멈춘다.
- `aim_follows_mouse_even_while_moving`: 오른쪽·위쪽 마우스에 맞게 조준하고, 마우스를 둔 채 이동하면 조준이 다시 계산된다.

**설명**
- 위에서 내려다본 보안관을 도형으로 그렸다. 파란 몸통 원, 그 위 갈색 모자 원, 마우스 방향으로 뻗은 두께 3px 총신이다. 4주차에 이미지 한 장을 `composite_draw`로 회전시켜 그리는 방식으로 바꾼다.

### 3. 발사와 총알 상태

**명세**
- 구역 총알은 6발이고, 시작할 때 모두 플레이어 손에 있다 (HELD).
- 왼쪽 클릭하면 총구에서 마우스 방향으로 초당 520px로 날아간다 (FLYING). 손의 총알은 1발 준다.
- 연사 간격은 0.18초다. 손에 총알이 없으면 클릭해도 아무 일도 없다.
- 날아간 총알은 1.6초가 지나거나 벽에 닿으면 바닥에 멈춘다 (FLOOR). 반사는 다음 단계에서 넣는다.
- 총알 객체는 구역을 시작할 때 6개만 만들고, 이후에는 상태만 바꾼다.

**검토**
- `bullet.py`: 상태를 `transitions`로 HELD → FLYING → FLOOR → HELD 순환으로 만들었다. 발사 위치와 각도는 `fire(x, y, angle, owner)` 트리거 인자로 넘기고, `before='launch'` 콜백이 받아 속도를 정한다.
- HELD 총알은 월드에 넣지 않고 플레이어의 `held` 목록에만 둔다. 발사할 때 월드와 충돌 쌍에 넣는다.
- **검토 중 발견한 문제:** 마우스를 움직이고 같은 프레임에 클릭하면, 조준이 다음 `update()`에서야 갱신되어 한 프레임 전 방향으로 나갔다. 발사 직전에 `update_aim()`을 부르도록 고쳤다.
- 발밑에 리볼버 여섯 칸처럼 남은 총알 수를 점으로 표시한다.

**실행**
- `docs/shots/w1_3_fire_flying.png`: 세 방향으로 쏜 총알이 날아가는 중, 발밑 표시는 3칸 남음.
- `docs/shots/w1_3_fire_floor.png`: 세 발 모두 벽에 닿아 바닥 총알(금색)로 멈춤.

**테스트**
- `start_with_six_bullets_in_hand`: 시작할 때 손에 6발, 월드에는 총알 없음.
- `click_fires_toward_mouse_immediately`: 마우스를 위로 옮긴 같은 프레임에 클릭해도 위로 나가고, 10프레임에 520×10/60px 이동한다. 위 문제를 고치기 전 코드에서는 이 테스트가 실패한다.
- `cooldown_blocks_rapid_double_click`: 연사 간격 안의 두 번째 클릭은 무시되고, 간격이 지나면 다시 나간다.
- `empty_gun_does_nothing`: 8번 클릭해도 6발만 나가고 총알 수는 6개 그대로다.
- `flying_bullet_stops_on_floor`: 1.6초 뒤 FLOOR가 되고 속도는 0, 위치는 벽 안쪽이다.

**설명**
- 총알을 쏠 때마다 새로 만들지 않는 것이 이 게임의 핵심 규칙(구역 총알 수 고정)을 코드로 보장하는 방법이다. 객체 수가 6개로 고정이라 상태만 확인하면 총알이 어디 있는지 항상 알 수 있다.
