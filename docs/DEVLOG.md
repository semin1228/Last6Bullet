# 개발 일지

AI가 만든 코드를 그대로 쓰지 않고, 기능마다 아래 순서로 확인한 뒤 커밋한다.

1. **명세:** 이번 단계에서 무엇이 되어야 하는지 정한다.
2. **검토:** 작성한 코드를 읽고 명세와 수업 구조에 맞는지 확인한다.
3. **실행:** 실제 창으로 띄워 스크린샷(`tools/shot.py`)을 남긴다.
4. **테스트:** 명세를 자동 점검(`tools/check.py`)으로 옮겨 고정 프레임(1/60초)으로 돌린다.
5. **설명:** 어떻게 동작하는지, 왜 그렇게 만들었는지 적는다.

```
C:\Python313\python.exe tools\check.py      # 자동 점검 (창 없이)
C:\Python313\python.exe tools\shot.py       # 스크린샷 (docs/shots/)
C:\Python313\python.exe main.py             # 게임 실행
```

## 1주차: 뼈대와 공유 총알

### 1. 프로젝트 뼈대

**명세**
- `main.py`를 실행하면 1280×720 창에 벽과 나무 바닥이 있는 빈 구역이 뜬다.
- ESC 또는 창 닫기로 종료한다.
- 수업 LEC15의 `game_framework`(모드 스택), `game_world`(레이어) 구조를 그대로 쓴다.

**검토**
- `game_framework.py`: LEC15 코드에 `frame_time`(직전 프레임 시간)만 추가했다. 이동을 프레임 수가 아니라 시간에 비례시키기 위해서다. 창을 끌다 멈춘 경우 한 번에 크게 움직이지 않도록 최대 0.05초로 자른다.
- `game_world.py`: LEC15의 레이어 관리에 충돌 쌍(`add_collision_pair`, `handle_collisions`)을 더했다. 충돌 판정은 `get_bb()` 사각형끼리 겹치는지로 본다. LEC15의 `add_oject` 오타는 `add_object`로 바로잡았다.
- `play_mode.py`: 이벤트 처리를 `dispatch(event)`로 분리했다. 자동 점검이 실제 게임과 같은 경로로 입력을 넣기 위해서다.
- pico2d 1.5.1의 `draw_rectangle(..., filled=True)`로 색을 채운 도형을 그릴 수 있어서, 1~3주차는 이미지 파일 없이 도형으로 개발한다.

**실행**
- `main.py`를 3초 동안 실행해 실시간 루프가 오류 없이 도는 것을 확인했다.
- 스크린샷: `docs/shots/w1_1_skeleton.png`

**테스트** (`tools/check.py`)
- `skeleton_runs_and_esc_quits`: 120프레임 동안 오류 없이 돌고, ESC 입력 시 `game_framework.running`이 꺼진다.

**설명**
- 자동 점검은 SDL 더미 화면으로 창 없이 돈다. 더미 화면에서는 픽셀을 읽을 수 없어서 스크린샷만 실제 창으로 찍는다.
- 상태 머신은 수업(LEC12~15)처럼 `transitions` 라이브러리의 `Machine`을 쓴다. PRD 15-2의 `state_machine.py`는 따로 만들지 않는다.

### 2. 플레이어 이동과 조준

**명세**
- 구역 가운데에서 시작해 WASD로 8방향 이동한다. 속도는 초당 200px이고 대각선도 같은 속도다.
- 반대 방향 키를 함께 누르면 멈춘다.
- 벽 밖으로 나갈 수 없다.
- 항상 마우스 쪽을 바라본다. 마우스를 그대로 두고 움직여도 계속 마우스를 향한다.
- 상태는 IDLE, RUN 두 가지다.

**검토**
- `player.py`: 눌린 키를 집합으로 모아 방향 벡터를 더하고 길이를 1로 맞춘다. 그래서 대각선이 √2배 빨라지지 않고, 반대 키는 서로 지워진다.
- 조준 각도는 마우스 이벤트가 올 때가 아니라 매 프레임 `atan2`로 다시 계산한다. 마우스를 멈춘 채 이동해도 조준이 따라간다.
- SDL 마우스 좌표는 좌상단 원점이라 `HEIGHT - 1 - y`로 뒤집는다.
- `zone.push_out()`: 원의 중심을 벽 안쪽에서 반지름만큼 떨어진 범위로 자른다.
- 다른 모드가 위에 올라오면 키업을 놓치므로 `release_all_keys()`로 모든 키를 뗀 것으로 처리한다 (LEC15 방식).

**실행**
- 스크린샷: `docs/shots/w1_2_move_and_aim.png`. 가운데에서 왼쪽 위로 약 133px(0.67초) 이동한 상태로, 총이 오른쪽 위 마우스를 향한다.

**테스트**
- `move_right_for_one_second`: D를 1초 누르면 x가 200px(±1) 늘고, 떼면 IDLE이 되어 멈춘다.
- `diagonal_has_same_speed`: W+D를 1초 누르면 이동 거리가 200px(±1)이다.
- `opposite_keys_cancel`: A+D를 함께 누르면 IDLE이고 움직이지 않는다.
- `cannot_leave_the_floor`: 왼쪽 아래로 10초 이동해도 벽 안쪽 모서리에서 반지름만큼 떨어진 곳에 멈춘다.
- `aim_follows_mouse_even_while_moving`: 오른쪽·위쪽 마우스에 맞게 조준하고, 마우스를 둔 채 이동하면 조준이 다시 계산된다.

**설명**
- 위에서 내려다본 보안관을 도형으로 그렸다. 파란 몸통 원, 그 위 갈색 모자 원, 마우스 방향으로 뻗은 두께 3px 총신이다. 4주차에 이미지 한 장을 `composite_draw`로 회전시켜 그리는 방식으로 바꾼다.

### 3. 발사와 총알 상태

**명세**
- 구역 총알은 6발이고, 시작할 때 모두 플레이어 손에 있다 (HELD).
- 왼쪽 클릭하면 총구에서 마우스 방향으로 초당 520px로 날아간다 (FLYING). 손의 총알은 1발 준다.
- 연사 간격은 0.18초다. 손에 총알이 없으면 클릭해도 아무 일도 없다.
- 날아간 총알은 1.6초가 지나거나 벽에 닿으면 바닥에 멈춘다 (FLOOR). 반사는 다음 단계에서 넣는다.
- 총알 객체는 구역을 시작할 때 6개만 만들고, 이후에는 상태만 바꾼다.

**검토**
- `bullet.py`: 상태를 `transitions`로 HELD → FLYING → FLOOR → HELD 순환으로 만들었다. 발사 위치와 각도는 `fire(x, y, angle, owner)` 트리거 인자로 넘기고, `before='launch'` 콜백이 받아 속도를 정한다.
- HELD 총알은 월드에 넣지 않고 플레이어의 `held` 목록에만 둔다. 발사할 때 월드와 충돌 쌍에 넣는다.
- **검토 중 발견한 문제:** 마우스를 움직이고 같은 프레임에 클릭하면, 조준이 다음 `update()`에서야 갱신되어 한 프레임 전 방향으로 나갔다. 발사 직전에 `update_aim()`을 부르도록 고쳤다.
- 발밑에 리볼버 여섯 칸처럼 남은 총알 수를 점으로 표시한다.

**실행**
- `docs/shots/w1_3_fire_flying.png`: 세 방향으로 쏜 총알이 날아가는 중, 발밑 표시는 3칸 남음.
- `docs/shots/w1_3_fire_floor.png`: 세 발 모두 벽에 닿아 바닥 총알(금색)로 멈춤.

**테스트**
- `start_with_six_bullets_in_hand`: 시작할 때 손에 6발, 월드에는 총알 없음.
- `click_fires_toward_mouse_immediately`: 마우스를 위로 옮긴 같은 프레임에 클릭해도 위로 나가고, 10프레임에 520×10/60px 이동한다. 위 문제를 고치기 전 코드에서는 이 테스트가 실패한다.
- `cooldown_blocks_rapid_double_click`: 연사 간격 안의 두 번째 클릭은 무시되고, 간격이 지나면 다시 나간다.
- `empty_gun_does_nothing`: 8번 클릭해도 6발만 나가고 총알 수는 6개 그대로다.
- `flying_bullet_stops_on_floor`: 1.6초 뒤 FLOOR가 되고 속도는 0, 위치는 벽 안쪽이다.

**설명**
- 총알을 쏠 때마다 새로 만들지 않는 것이 이 게임의 핵심 규칙(구역 총알 수 고정)을 코드로 보장하는 방법이다. 객체 수가 6개로 고정이라 상태만 확인하면 총알이 어디 있는지 항상 알 수 있다.

### 4. 벽과 장애물 반사

**명세**
- 구역에 술집 테이블 3개(사각형 장애물)를 놓는다.
- 날아가는 총알은 벽이나 테이블에 닿으면 튕긴다. 최대 2번 튕기고, 세 번째로 닿으면 그 자리에 떨어진다.
- 튕길 때는 겹친 깊이가 얕은 축의 속도를 뒤집는다 (PRD 15-5).
- 한 번에 6px 이하로 나눠 움직여서, 프레임이 느려도 얇은 벽을 뚫지 않는다 (PRD 18장 위험 요소).
- 플레이어도 테이블을 통과할 수 없다.

**검토**
- `zone.bounce()`: 벽은 넘어간 축의 속도를 뒤집고 안쪽으로 되돌린다. 구석에서 두 벽에 동시에 닿으면 두 축을 모두 뒤집되 한 번 튕긴 것으로 센다.
- `zone.push_out()`: 원과 사각형의 가장 가까운 점을 구해 반지름보다 가까우면 바깥으로 민다. 원 중심이 사각형 안이면 가장 가까운 변으로 꺼낸다.
- `bullet.update()`: 한 프레임 이동 거리를 6px 이하 조각으로 나눠 조각마다 반사를 검사한다.
- **테스트로 찾은 버그:** 처음에는 장애물의 어느 쪽으로 꺼낼지를 "총알 중심이 장애물 가운데보다 왼쪽인가"로 정했다. 두께 6px 벽에서는 중심이 한 번에 가운데를 넘어가 반대편으로 꺼내지면서 벽을 통과했다. 꺼낼 쪽과 깊이를 **날아온 방향(속도)** 기준으로 바꿔 고쳤다.

**실행**
- `docs/shots/w1_4_bounce.png`: 테이블 아래에서 세 방향으로 쏜 총알의 경로(파란 점)와 멈춘 자리(금색). 테이블 아랫면, 오른쪽 테이블 모서리, 아래쪽 벽에서 튕긴다. 경로 점은 스크린샷 도구에서만 그린다.

**테스트**
- `bullet_bounces_off_right_wall`: 오른쪽 벽에 맞으면 x 속도가 뒤집히고 튕긴 횟수가 1이다.
- `third_hit_lands_the_bullet`: 수명을 늘려 두고 쏘면 세 번째로 닿을 때 바닥에 떨어진다.
- `bullet_bounces_off_table`: 테이블 아래에서 위로 쏘면 아랫면에서 튕기고 테이블을 통과하지 않는다.
- `player_cannot_walk_through_table`: 테이블 쪽으로 2초 걸어도 테이블 아래 변에 멈춘다.
- `no_tunneling_in_500_random_shots`: 무작위 위치·각도 500발을 수명이 끝날 때까지 돌리며 매 프레임 벽 밖이나 테이블 안에 있는 총알이 없는지 본다.
- `thin_wall_is_not_tunneled_at_slowest_frame_rate`: 두께 6px 벽을 세우고, 가장 느린 프레임(0.05초, 한 프레임 26px)에서 200발을 쏴도 벽을 넘는 총알이 없다. 나눠 움직이기를 끄면(`BULLET_SUBSTEP=1000`) 이 테스트가 실패하는 것도 확인했다. 즉 이 테스트는 나눠 움직이기와 방향 기준 꺼내기를 함께 검증한다.

**설명**
- 지금 테이블은 두께가 70px라 나눠 움직이기 없이도 뚫리지 않는다. 이 장치가 실제로 필요한 곳은 3주차 기차 구역의 짐받이 턱처럼 얇은 장애물이라, 미리 얇은 벽으로 테스트를 만들어 두었다.

### 5. 바닥 총알 줍기와 튕긴 총알 자해

**명세**
- 바닥 총알 위를 지나가면 즉시 줍는다. 총알은 HELD가 되어 월드에서 빠지고 손으로 돌아온다.
- 아직 튕기지 않은 내 총알은 나를 통과한다.
- 벽이나 테이블에 한 번이라도 튕긴 총알은 누구든 맞는다 (PRD 3장 규칙 5). 맞으면 체력 -1, 1초 무적(깜빡임)이고 총알은 그 자리에 떨어진다.
- 발사 후 0.12초 동안은 사람에게 맞지 않는다.
- 체력은 4칸(보통 난이도)이고 위쪽 벽에 표시한다. 체력 0일 때의 게임 오버는 2주차에 넣는다.

**검토**
- 충돌 쌍 `player:bullet`으로 처리한다. `get_bb()` 사각형이 겹치면 `Player.handle_collision()`이 원 중심 거리를 한 번 더 확인한다. 사각형 모서리끼리만 겹친 대각선 상황에서 줍거나 맞지 않게 하기 위해서다.
- 판정 규칙은 `Bullet.can_hit_anyone()` 한곳에 모았다 (FLYING, 튕긴 횟수 1 이상, 발사 후 0.12초 지남). 2주차에 적이 맞는 판정도 같은 함수를 쓴다.
- 날아가는 총알은 튕기기 전 파랑, 튕긴 뒤 주황으로 그려 "누구든 맞는 총알"을 구분한다 (PRD 14장 총알 구분).
- **테스트로 확인한 동작:** 맞힌 총알은 내 발밑에 떨어지므로 다음 프레임에 바로 주워진다. 체력은 잃지만 그 총알은 내 손에 들어온다. 규칙상 자연스러운 결과라 그대로 두고, 2주차에 적이 쏜 총알에 맞을 때도 괜찮은지 플레이 테스트로 다시 본다.
- 새 규칙 때문에 4단계 테스트 두 개(`third_hit_lands_the_bullet`, `bullet_bounces_off_table`)가 실패했다. 튕겨 돌아온 총알이 쏜 자리에 서 있던 플레이어를 맞혔기 때문이다. 이 테스트들은 반사만 보려는 것이라 쏜 뒤 플레이어를 경로 밖으로 옮기도록 고쳤다.

**실행**
- `docs/shots/w1_5_bounced_back.png`: 오른쪽 벽 앞에서 벽을 쏘자 튕겨 돌아오는 총알(주황).
- `docs/shots/w1_5_hurt.png`: 맞아서 체력 3칸, 맞은 총알을 주워 발밑 표시는 다시 6칸.

**테스트**
- `walking_over_floor_bullet_picks_it_up`: 바닥 총알 쪽으로 걸어가면 주워서 손에 6발, 월드에 총알 없음.
- `own_unbounced_bullet_passes_through`: 튕기지 않은 내 총알은 몸을 통과한다.
- `bounced_bullet_hurts_and_drops`: 튕긴 총알에 맞으면 체력 -1, 무적이 켜지고 총알은 발밑에 떨어져 주워진다.
- `bullet_that_hit_you_drops_at_your_feet`: 맞힌 총알은 맞은 자리에 FLOOR로 떨어진다.
- `invincibility_blocks_second_hit`: 무적 중 두 번째 총알은 무시되고, 무적이 끝나면 다시 맞는다.
- `shooting_a_wall_up_close_hurts_yourself`: 실제 상황 재현. 벽 바로 앞에서 벽을 쏘면 튕겨 나온 내 총알에 맞는다.

### 6. 총알 장부 (AmmoLedger)

**명세**
- 매 프레임 충돌 처리가 끝난 뒤 손 + 바닥 + 공중 총알이 6발인지 확인한다.
- 각 총알의 상태가 위치와 맞는지(손에 있으면 HELD, 월드에 있으면 HELD가 아님), 같은 총알이 두 곳에 있지 않은지도 본다.
- 어긋나면 화면 위쪽에 빨간 경고를 띄우고 콘솔에 한 번 알린다.
- F1로 "손 · 바닥 · 공중 = 합계" 표시를 켜고 끈다.

**검토**
- `ammo_ledger.py`: 총알을 손에 드는 쪽 목록(`holders`)을 받아 센다. 2주차에 적이 총알을 들게 되면 목록에 적을 더하기만 하면 된다.
- 검사는 `play_mode.update()`에서 충돌 처리 뒤에 부른다. 줍기처럼 충돌 처리 중에 총알이 손으로 옮겨 가는 순간을 중간 상태로 세지 않기 위해서다.
- 글자는 Windows 기본 글꼴(맑은 고딕)로 그린다. 글꼴 파일은 저장소에 넣지 않고, 없으면 글자 없이 실행된다.

**실행**
- `docs/shots/w1_6_ledger.png`: F1을 켠 상태. 오른쪽 위 "손 3 · 바닥 1 · 공중 2 = 6"이 화면의 발밑 표시 3칸, 바닥 총알 1발, 날아가는 총알 2발과 일치한다.

**테스트**
- `ledger_counts_hand_floor_and_air`: 두 발을 쏘면 손 4, 공중 2, 바닥에 떨어진 뒤에는 손 4, 바닥 2.
- `ledger_catches_a_lost_bullet`: 버그를 흉내 내 바닥 총알을 줍지 않고 지우면 "총알 수 5 (기대 6)"을 잡아낸다.
- `ledger_catches_a_wrong_state`: 손에 있는데 상태가 FLOOR인 총알을 잡아낸다.
- `random_play_for_50_seconds_keeps_six_bullets`: 무작위로 이동·조준·발사하고 주기적으로 바닥 총알을 주우러 가는 가상 플레이어를 3000프레임(50초) 돌린다. 매 프레임 장부에 문제가 없고, 플레이어와 총알이 벽 밖이나 테이블 안에 없다. 이번 실행에서 16발을 주웠다.

**테스트를 만들며 고친 점 (테스트 코드 쪽)**
- 처음에는 50초 동안 한 발도 줍지 않아 "검사가 의미 없음" 조건에 걸렸다. 두 가지 원인이 있었다.
  1. `sim.step(1, before=act)`는 한 프레임만 돌리므로 `act`에 넘어가는 프레임 번호가 항상 0이었다. 그래서 줍기 구간에 들어가지 못하고 매 프레임 키가 무작위로 바뀌었다. 전체 프레임 번호를 넘기도록 고쳤다.
  2. 가상 플레이어가 바닥 총알로 직선으로만 걸어가다 테이블에 막혔다. 제자리면 잠깐 무작위 방향으로 비켜 걷게 했다.
- 게임 코드에는 문제가 없었다. 줍기 자체는 따로 확인한 디버그 실행에서 정상이었다.
